# Final build audit

## C05 connection regression — decision before edits (2026-09-26)

User observation on delivered C04: sign-in, console discovery and connection failures; screenshot shows stream start ending in `network request timed out`. Recovered source matches C04 input map `2e4a18d05b7e1f1606e4f6dfdcc33d46238bcb4674c86d2821d2e3728d0020ce`. The screenshot does not identify DNS/TLS/header timing or demonstrate an Xbox service outage.

**High, confirmed compatibility regression:** `src/http.rs` introduced 5-second connect/read limits beneath the existing 10-second overall request budget used by `src/api_xbox/{api,auth}.rs`. Locked reqwest 0.12.28 creates its read-timeout future when executing the request, before response headers, so this is also an earlier response-header cutoff, not merely a body safety limit. All three reported operations share this client. A valid response between five and ten seconds could pass the prior implementation and fail C04. Reproduce against the actual production HTTP client with a local service delaying headers six seconds; preserve the failure before correcting anything. Restore the existing ten-second budget consistently for connection/read/overall stages, without extending the original total deadline, relaxing payload caps, enabling redirects, weakening TLS, or automatically retrying session-creation POSTs. This verifies an introduced failure mechanism; it does not establish the elapsed network stage on the user's Vita or solve media latency.

Planned files: `src/http.rs`, `tests/release-hardening/src/tests.rs` for deadline regression, end-to-end budget, cancellation-before-headers, zero automatic POST replay, and safe error classification. `src/api_xbox/api.rs` will add fixed operation labels to errors (console listing versus session creation/signaling), without echoing server paths/tokens. `src/app/ui/screens/error.rs` will remove unconditional endpoint disclosure; the screenshot confirms raw regional hosts currently appear in every error. Account data and Home no-termination policy remain unchanged. Acceptance: six-second valid service response fails C04 and passes correction, >10-second header/body request still times out, cancel joins/closes pending request, no hidden retry or secret leakage; all host gates, native preflight/check/package and identity checks run. Native strict lint and hardware gates stay explicit if still failing. Source changes are limited to these confirmed regressions and their error context; no media tuning.

C05 follow-up before edit: `src/app/entry.rs` uses the generic error-screen constructor when device-code acquisition fails; `src/app/command.rs` routes that screen's Back action to ModeSelect despite no credentials. Use the existing sign-in-error constructor so Back returns to InitializeAuthentication and retries the saved login/device-code flow. No token erasure or fresh account flow is forced. Also place session-creation context at `src/app/stream_session/connection.rs` after the existing Cloud free-to-play fallback, rather than inside the inner request: wrapping the inner error would break its exact string guard. These are inspection-backed control-flow corrections, not additional deadline changes.

Pre-edit baseline: `8d9cba8b22b82cddfe9e81e352558132c2fcbbc6`, branch `latency-root-cause`. This audit precedes source changes. No release readiness or hardware latency claim is made.

C05 execution outcome: the actual production HTTP client fails the six-second header fixture before correction and passes after it. All 25 hardening tests, 238 total Rust test executions, 27 Python tests and 11 strict host lint suites pass. Native check passes; native strict Clippy remains failed on existing unused members. Sign-in Back state flow and Cloud fallback placement were reviewed against actual callers; no physical Vita/Xbox flow was executed. See `C05_CONNECTION_RESULTS.md` and `verification/c05` in the review bundle for actual commands, durations, provenance and limitations. This verified client regression is not proof of the specific network timing on the user's device or a media-latency root cause.

## Scope and intent

GreenVita is a PS Vita homebrew Xbox Home Remote Play / Cloud streaming client, derived from Day-OS/green-vita. The runtime target is `armv7-sony-vita-newlibeabihf`; Windows and Unix wrappers are build-host support, not desktop application ports. All production Rust modules under `src/`, configuration, workflows, packaging scripts, assets, font notices, and the locked graph were inventoried/reviewed. Vendored RTC changes and existing incident/test records were reviewed as dependencies; this is not a claim to have formally verified every upstream dependency. MPL-2.0 and upstream attribution must remain. Font notices exist in source but are absent from the installable package. Xbox trademarks are not project-owned.

The lockfile has 325 packages. Cargo.toml has no optional application features. Native requirements include VitaSDK, SDL2/GXM, Opus, AVCDEC, AppUtil Safe Memory, pkg-config, C/C++ tools and nightly Rust with rust-src/build-std. The last known native candidate used SDK digest `sha256:351f167c6c0c502baf92502b779cc4b52e9f82ac83efd172911c3ce37b3199cc`, Rust 1.97.0-nightly (4b0c9d76a, 2026-05-10). A minimum compiler for the full locked graph was not established; pin the tested compiler instead of asserting an untested MSRV.
